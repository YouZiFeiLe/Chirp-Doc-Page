# 音频设置、降噪与个人资料

除了基础的进房语音外，Chirp 在四个客户端上提供了细粒度的本地音频控制、降噪预设与语音激活（VAD）门控，以及可实时同步的个人昵称、头像和社交关系管理。

## 音频处理预设与 RNNoise 降噪

Chirp 默认内置了基于深度学习的开源降噪引擎 **[RNNoise](https://jmvalin.ca/demo/rnnoise/)**，并针对各操作系统的音频底层特性提供了三种可选处理预设。你可以在「声音设置」中按当前麦克风和环境噪音情况切换：

| 平台 | 可选音频预设 | 工作机制与适用场景 |
| --- | --- | --- |
| **macOS / iOS** | **Apple 系统处理 + RNNoise（默认）**<br>Apple 系统处理<br>WebRTC 回声消除 + RNNoise | 默认同时利用 Apple 硬件级回声消除（AEC）/ 自动增益（AGC）与 RNNoise 降噪（iOS 配合 [CallKit](https://developer.apple.com/documentation/callkit) 保活）；遇到系统策略限制或特定外接声卡兼容问题时，可切换至「WebRTC 回声消除 + RNNoise」。 |
| **Windows** | **系统通信处理 + RNNoise（默认）**<br>系统通信处理<br>软件回声消除（Sonora）+ RNNoise | 基于 [WASAPI](https://learn.microsoft.com/windows/win32/coreaudio/wasapi) 与 Rust Sonora（WebRTC AEC3 + AGC2）和 `Chirp.RNNoise.dll`。若笔记本或外置声卡自带驱动回声消除效果不佳，可改用软件回声消除预设。 |
| **Android** | **WebRTC 回声消除 + RNNoise（默认）**<br>WebRTC 内置降噪<br>仅回声消除 | 基于 [Core-Telecom](https://developer.android.com/develop/connectivity/telecom/voip-app/telecom) 与自定义音频管线，默认启用 WebRTC 回声消除搭配 RNNoise；需要对比原声通透度时可切至内置降噪或仅开启回声消除。 |

::: tip 切换预设前先做本机试听
「声音设置」中提供「**本机麦克风测试**」与「**停止并试听**」功能（为避免音频独占冲突，测试与房间通话互斥，进入房间时会自动结束测试）。点击开始测试后可对着麦克风说话（最长采集约 10 秒），停止并试听会立刻回放**最近 3 秒经过当前降噪与语音激活处理后的真实声音**，方便你在不打扰朋友的情况下调好效果。
:::

## 语音激活（VAD）与音量控制

- **语音激活门控（VAD）**：默认关闭（即开麦后持续发送音频流）。开启后，只有当麦克风采集电平高于设定阈值时才会送入编码发送：
  - 默认阈值：**−45 [dBFS](https://en.wikipedia.org/wiki/DBFS)**，可在 **−80 dBFS 至 −10 dBFS** 之间精细调节。
  - **静音优先级始终最高**：手动关闭麦克风时，无论环境音多大都不会触发发送；界面上的实时音量电平条展示的是门控前的原始输入电平，便于观察环境底噪以校准阈值。
  - VAD 开关与阈值均只保存在本机，切换预设或重新连接后依然保留。
- **静音 vs. 停止收听（Deafen）**：开麦/静音控制自己是否对外发声，停止收听则同时切断播放所有远端成员的语音以及进出房提示音（恢复收听后不会补播积压的旧提示音）。
- **成员独立音量**：在房间成员列表中，你可以为每位朋友单独调节 **0% 至 200%** 的本地播放音量，该设置仅影响你自己的听感，不会改变对方的采集增益。

## 跨平台通话与窗口行为差异

- **macOS**：关闭最后一个主窗口时，**当前语音通话仍会在后台继续保持**，重新打开窗口即可回到同一房间；多窗口之间共享静音、切房和聊天状态。只有在彻底退出应用（`Cmd + Q`）时才会离房。
- **Windows**：关闭主窗口（点击右上角 `×`）会**直接结束当前通话并彻底退出 `Chirp.exe` 与后台协议进程 `Chirp.Protocol.exe`**，对端会立刻看到你离开房间。若已在设置中启用 Windows Hello 登录恢复且凭证未到期，下次打开可通过 Windows Hello 解锁恢复（但仍需重新进入房间）。
- **iOS / Android**：支持在锁屏或切换后台期间保持通话与按键轮换（Android 通过 Core-Telecom 与前台服务保活），普通切回直接沿用运行中的会话。若从系统最近任务列表中**强行划掉 Chirp 进程**，通话与内存会话会立即终止；在支持且有效的 20 小时恢复窗口内，重开应用会唤起面容或指纹解锁恢复登录（主动退出或无恢复记录时才需重新 Passkey 登录）。

## 个人资料与头像

你可以在客户端的个人资料页面随时修改昵称与头像（通话过程中修改会自动同步给房内成员，且**不会**中断通话或触发重新配钥）：

- **展示昵称**：支持 1 至 80 个任意字符（中文、英文、Emoji 均可），保存时会自动去除首尾多余空白，并禁止包含不可见控制字符。注意：修改展示昵称不会改变你注册时的英文登录账号名。
- **头像规格限制**：服务端接口直接接收静态 **JPEG** 或 **PNG** 图片，客户端也会在上传前自动帮你转换 HEIC 等常见静态图片格式。限制为文件大小 **小于 5 MB（5,000,000 字节）**，单边分辨率不超过 **8192 像素**，总像素不超过 **3200 万像素**。

## 好友与「设备互认」有什么区别？

很多成员第一次使用时会疑惑：为什么我已经把朋友「加为好友」了，进房间时却还是提示「待核验」？

| 概念 | 作用范围 | 是否决定通话加密权限？ |
| --- | --- | --- |
| **好友列表** | 单向添加，方便记录认识的账号、查看社交列表。 | **否。** 单向或双向加好友都不会自动授予任何密码学信任。 |
| **设备信任（SAS 互认）** | 绑定对方的**账号根身份 + 具体某台设备的公钥**，核对过一次后该台设备在以后跨房、重登、换钥时都无需再核验。 | **是。** 房间内的所有设备都必须与你完成过双向设备互认，OpenMLS 才会为其派生内容密钥并开放通话。 |

简而言之：**好友认的是人，安全码认的是设备**。当你的朋友更换了新手机或新电脑后，虽然他仍在你的好友列表里，但大家仍需要为这台新设备核对一次三组安全码，以防止有人冒用他的账号接入未知设备。

## 界面语言与诊断日志

- **语言偏好**：客户端支持「**简体中文**」、「**English**」与「**跟随系统**」三种选项（默认跟随系统或简体中文）。在设置中切换界面语言立即生效，**不会**断开登录或中断正在进行的通话。
- **本地诊断日志（`.chirplog`）**：默认处于**关闭**状态，可在「设置 → 日志管理」中手动开启。开启后，客户端只会在本地记录脱敏后的操作耗时、网络状态码与加密帧统计（绝不记录聊天原文、附件内容、服务器地址、Passkey 或密钥），并按 24 小时滚动清理。排查疑难问题时，你可以点击「**导出日志**」生成最近 24 小时的 `.chirplog` 文件发给开发者分析，也可以随时点击「清除日志」。[客户端日志格式规范](/reference/chirplog)
