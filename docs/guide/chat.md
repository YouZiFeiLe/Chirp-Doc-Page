# 房间聊天与文件传输

进入房间并完成全员设备互认后，你就可以打开房间侧边栏或聊天页收发文字消息和文件。文字与文件传输和语音开麦相互独立——即使保持静音，依然可以正常发送文字和附件。

## 临时房间聊天

为了贯彻极简隐私原则，**Chirp 服务器完全不保存任何房间聊天记录**。所有文字和文件描述都通过端到端加密的 [WebRTC](https://www.w3.org/TR/webrtc/) 数据通道在当前在线成员之间直接传输：

- **消息长度限制**：单条消息最多支持 **4096 个 UTF-8 字节**（注意：1 个汉字通常占 3 个字节，1 个 Emoji 通常占 4 个字节），且不能是纯空白字符。过长的内容请拆分为多条发送。
- **本地会话缓存**：每个客户端在本次入房期间最多在内存中保留最近的 **1000 条**文字与附件记录。
- **记录何时清空**：当你主动**离开房间、切换到另一个房间、被管理员移出、重新登录或退出应用**时，本次房间的聊天记录与未发出的草稿会立即清空。重新进入房间或晚些时候新加入的朋友，均无法看到此前发过的任何消息。
- **安全状态变动时的提示**：当房内有成员进出或出现未核验设备时，聊天发送会暂时锁定，直到房间重新完成安全配钥后再恢复发送。

## 发送与自动接收附件

Chirp 的附件传输同样采用端到端加密：发送端在本机用随机生成的独立文件密钥把文件加密为密文后再分块上传，**服务器只负责临时托管密文，既看不到原文件名和缩略图，也拿不到文件解密密钥**。文件解密密钥仅随加密聊天描述直接送达当时在线的房内成员。

1. **确认在线与房内就绪**：发送文件前，请确认想接收的朋友**已经在当前房间内**且房间安全状态已就绪。点击聊天栏中的附件按钮选择图片或普通文件：
   - **普通文件**：单个原文件最大支持 **100 MiB**（支持 0 字节空文件）。
   - **可预览图片**：支持 JPEG、PNG、HEIC、WebP、GIF 等常见格式，最大支持 **20 MiB** 且总像素不超过 **6000 万像素**。GIF 在聊天气泡中仅预览首帧，导出后会完整保留原始动图。
2. **发送端加密与上传**：客户端在本机加密文件并上传至服务器暂存。如果上传过程因网络波动暂停，可在有效期内点击继续；未完成的上传自创建起最多保留 **15 分钟**。
3. **接收端自动下载与校验**：上传完成后，发送开始时就在房内且在线的接收端会自动按队列下载密文，并在本机核对完整哈希与逐记录加密标签后解锁预览。
4. **错过投递的规则**：如果朋友在**你点击发送之后**才进房，或者接收过程中彻底离房/断网超过宽限时间（6 秒），他将无法补收这个文件，需要他在房内就绪后由你重新选择发送。

> [!TIP] 高清通话与大文件并传时的智能限速
> 为避免大文件上传下载挤占实时语音带宽，客户端默认将单方向传输速率控制在 8 MiB/s；当检测到当前通话音轨质量较差（`poor`）或网络抖动达到 40 ms 时，会自动降速至 512 KiB/s 以优先保证语音清晰流畅。

## 离房前务必导出重要文件

**看到聊天列表里的缩略图或「已下载」，只代表该文件目前保存在本次房间的临时加密缓存中。** 已完整上传的附件在服务端最多只保留 **15 分钟** 分发窗口；一旦所有在线接收者都已确认收到或离开房间，服务器上的密文副本会**立刻被永久删除**。

想永久留存的照片或文档，请在离开或切换房间前，点击附件卡片上的「**导出**」，将其保存到系统「下载」、相册或你指定的目录中，并确认文件已写入目标路径。

| 常见场景 | 附件会发生什么 |
| --- | --- |
| **发送者中途离房** | 尚未传完的上传会被取消；已经上传完成的文件，其余原在线接收者仍可继续下载完。 |
| **接收者清空附件缓存** | 已接收的临时缓存与密钥会被清理，且无法再从服务器补回；此后仍可正常收发新附件。 |
| **接收者离房或切房** | 原房间的聊天列表与加密附件缓存全部销毁；切换到新房间后使用独立的会话缓存。 |
| **接收者已完成导出** | 导出操作会将文件明文直接写入你选择的系统位置，与 Chirp 缓存完全隔离；之后即使离房或卸载缓存，已导出的文件依然安好。 |
