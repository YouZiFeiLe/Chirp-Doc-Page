# 设备备份与换机恢复

Chirp 采用**单设备在线 + 客户端独立密钥**的设计：每个账号同一时间只允许一台客户端处于已登录状态，而真正用于签署设备身份的「账号根私钥」**只保存在你自己的手中，不会上传至服务器**。因此，无论是初次使用、更换新设备，还是旧设备遗失，理解身份备份与授权机制都至关重要。

| 你当前的情况 | 推荐操作路径 |
| --- | --- |
| **首次登录的新账号** | 在本机生成账号根密钥，设置强密码并导出 `.chirpkey` 文件完成绑定。 |
| **换了新手机/电脑，手头还有旧设备** | 新设备先用 Passkey 登录，再让**旧设备扫描新设备的授权二维码**，核对安全码后批准。 |
| **旧设备不在身边或已重置，但留有 `.chirpkey`** | 新设备用 Passkey 登录后，选择导入 `.chirpkey` 并输入原密码解锁恢复。 |
| **旧设备丢失，且既无 `.chirpkey` 又忘了密码** | 原加密身份**无法找回**（管理员也无法解锁）。需要联系管理员停用/删除旧账号后重新注册。 |

::: tip 准备彻底抹掉或卖掉旧手机？
在重置旧设备前，请先确保新设备上已经同步好你的 **[Passkey](https://fidoalliance.org/passkeys/)**（例如已通过 iCloud 钥匙串、Google 密码管理器或硬件密钥同步），并用新设备实际完成一次 Chirp 登录和身份恢复验证，确认无误后再抹除旧设备。
:::

## 首台设备：创建并妥善保存 `.chirpkey`

首次获批登录的设备会引导你创建账号的 [Ed25519](https://datatracker.ietf.org/doc/html/rfc8032) 根身份并导出离线恢复文件（`.chirpkey`）：

1. **设置高强度恢复密码**：输入两次不少于 **16 个字符**（严格按 Unicode 标量与 UTF-8 字节计算，最长 1024 字节）的密码。客户端会**原样保留大小写以及首尾空格**，支持直接从密码管理器粘贴。
2. **导出到可靠位置**：将生成的 `.chirpkey` 文件（默认建议命名为 `<用户名>_<日期>_<平台>.chirpkey`）保存到换机后依然能读取的位置，例如本地备份盘或加密网盘。**建议将密码与文件分开保管**（密码存密码管理器，文件单独备份）。
3. **等待确认并完成激活**：保存成功后返回客户端确认页，在阅读安全提示并等待 5 秒后点击确认，客户端才会正式向服务器提交公钥绑定。

> [!NOTE] `.chirpkey` 里包含什么？
> 它只包含你在该服务器上的**账号根私钥与公钥元数据**（采用 [Argon2id](https://datatracker.ietf.org/doc/html/rfc9106) + [AES-256-GCM](https://csrc.nist.gov/pubs/sp/800/38/d/final) 加密）。它**不包含**你的 Passkey、旧设备的独立私钥、任何聊天记录或文件附件。即使换了完全不同的平台（例如从 iPhone 换到 Windows 电脑），同一份 `.chirpkey` 也能通用恢复。详细二进制规范见[`.chirpkey` 文件格式](/reference/chirpkey)。

## 换机方式一：用旧设备扫码授权

<VerificationFlowDiagram />

如果你手头还有一台已经登录过、且未被撤销的旧设备（即使它之前被另一台设备踢下线，只要设备身份本身依然有效，依然具备授权资格）：

1. **新设备发起请求**：在新设备用原账号的 Passkey 登录后，进入身份恢复引导，选择「**使用已有设备授权**」，屏幕上会生成一个带有时效签名的二维码（有效期 **5 分钟**）。保持此页面不要关闭。
2. **旧设备扫码或导图**：在旧设备打开 Chirp 设置里的「**授权新设备**」：
   - 可以直接使用摄像头扫描新设备屏幕上的二维码；
   - 如果两台设备不在一处，也可以在新设备导出二维码 PNG 图片发送给自己，再在旧设备选择「**导入二维码图片**」（支持 ≤ 8 MiB、单边 ≤ 4096 像素的常见图片格式）。
3. **核对三组安全码并验证本机身份**：
   - 使用摄像头扫码时，两边屏幕会同时显示 3 组安全码，逐组核对完全一致后分别确认。
   - **使用图片导入时**，旧设备会隐藏自己计算的数字，要求你在旧设备上**手动输入新设备当前屏幕显示的全部 3 组数字**（连续输错 3 次会立即中止本次配对）。
   - 最后在旧设备上通过系统指纹、面容或开机密码确认签发。
4. **新设备接管会话**：旧设备签发新设备证书后，新设备会自动完成登记并进入房间列表。**只有当新设备彻底激活成功后，旧设备的登录会话才会退出**，避免中途断网导致两边同时掉线。

## 换机方式二：导入 `.chirpkey` 恢复文件

1. 在新设备上使用同一账号的 Passkey 登录同一服务器地址，在恢复选项中选择「**使用恢复文件**」。
2. 选取之前保存的 `.chirpkey` 文件，核对文件名并输入当时设定的恢复密码（注意区分大小写和首尾空格）。
3. 客户端会在本机解密验证根密钥与服务器账号是否匹配，随后为这台新设备生成一套全新的本地设备私钥并联网完成激活。

## 换机后的好友核验与设备撤销

- **好友需要重新核验这台新设备**：你的朋友以前核验并信任的是你的「旧设备公钥」。当你使用新设备初次和朋友进入同一房间时，双方需要为这台新设备重新核对一次 3 组安全码。
- **设备丢失时及时撤销**：如果某台旧设备遗失或不再使用，你可以在当前正常使用的设备「设置 → 设备管理」中核对设备名称、平台和指纹后**撤销丢失的设备**。
  - 为防止误锁死自己，系统不允许自助撤销「当前正在使用的设备」，且要求成员至少保留一台有效设备。
  - 一旦被撤销，该设备将作为永久墓碑记录在服务端授权日志中，**即使用原证书或恢复文件也无法复活那台已撤销的设备**（但你可以使用恢复文件为账号重新登记一台全新设备）。
  - 如果需要彻底封禁账号或强行撤销最后一台设备，须由管理员在管理台操作。[管理员维护指南](/hosting/admin-console)

## 清空本地数据

在客户端登录页（即使尚未登录或当前账号已被封禁），你都可以找到「**清空本地数据**」入口。确认执行后，客户端会彻底清除本机保存的设备私钥、证书、好友与信任检查点、黑名单缓存、本地诊断日志以及服务器配置记录，让客户端恢复到刚安装时的纯净状态。此操作**不会删除**你在云端/硬盘外部另行保存的 `.chirpkey` 备份文件，也不会修改服务器端数据。
