# 选择和安装客户端

Chirp 的全部核心体验——实时加密通话、临时文字聊天、端到端文件传输以及本地设备密钥保管——均在**原生客户端**中完成；浏览器只负责账号申请、Passkey 身份验证以及管理员的后台管理。

::: tip 获取匹配服务器版本的安装包
请向你的服务器管理员索取客户端安装包与完整的服务器 HTTPS 地址。如果管理员自行更换了服务器的[授权签名密钥](/reference/authorization-keys)（而非使用开源版默认密钥），客户端必须使用由同一套公钥编译构建的安装包，否则登录后会因无法验证服务端授权签名而被拦截。
:::

## 各平台系统要求与安装方式

| 平台 | 最低系统与架构要求 | 安装与分发方式 | 注意事项 |
| --- | --- | --- | --- |
| **macOS** | macOS 27 及以上<br>Apple Silicon（`arm64`） | 打开维护者分发的 `.dmg` 镜像，将 Chirp 拖入「应用程序」。 | 开源发布包带有开发者签名并经过 Apple 公证（Notarization）；关闭窗口时默认保留后台通话，完全退出需使用 `Cmd + Q`。 |
| **iOS** | iOS 27 及以上（`arm64`） | 向管理员取得 `.ipa` 安装包。 | 当前未上架 App Store，需使用你的 Apple 开发者/自签工具签名后安装到 iPhone。 |
| **Windows** | Windows 11 24H2 及以上<br>`x64`（系统内部版本 ≥ `26100`） | 运行单用户安装包 `Setup.exe` 或 `MSIX` 包。 | `Setup.exe` 内置所需 .NET 与 [WinUI 3](https://learn.microsoft.com/windows/apps/winui/winui3/) 运行时；默认构建未做 Authenticode 代码签名，遇到 SmartScreen 提示时请向管理员核对哈希与来源。Arm64 Windows 尚未验证。 |
| **Android** | Android 15（API 35）及以上<br>`arm64-v8a` 或 `x86_64` | 安装管理员提供的 `.apk`（单包同时包含两种架构）。 | **Android 17** 访问局域网内自建服务时，需在客户端「我的 → 使用偏好」中授予局域网访问权限；部分厂商定制系统需留意后台保活与 Passkey 管理器兼容性。 |

### 如何快速确认本机版本与架构？

- **Mac**：点击屏幕左上角苹果菜单 ` → 关于本机`，查看芯片类型（需为 M 系列 Apple 芯片）和 macOS 版本。
- **Windows**：按下 `Win + R`，输入 `winver` 回车查看「版本号」与「OS 内部版本」（须不低于 `26100`）；在「设置 → 系统 → 系统信息」中确认系统类型为「基于 x64 的处理器」。

## 首次启动与登录方式

1. **填写完整服务器地址**：打开 Chirp 后，输入管理员给你的完整 HTTPS 地址。如果服务器使用了自定义端口，**必须保留端口号**（例如 `https://voice.example.com:8443`）。正式发行版客户端强制要求 HTTPS；只有面向开发调试的 Debug 构建才允许连接 `localhost` 的 HTTP 地址。
2. **确认服务器信息**：客户端会自动请求服务发现接口并校验服务器版本策略。确认显示的服务器地址无误后，选择以下任意一种方式登录：
   - **本机 Passkey 登录**：拉起系统浏览器或认证弹窗，使用本机或密码管理器中的 [Passkey](https://fidoalliance.org/passkeys/) 验证后自动回调客户端（回调协议为 `cn.youzifeile.chirp://`、`cn.youzifeile.chirp.windows://` 或 `cn.youzifeile.chirp.android://`）。在 Windows 上，浏览器页完成验证后会通过最多 **60 秒**指数退避轮询确认协议客户端已顺利接管回调，防止系统拦截自定义 URL Scheme 导致无响应。
   - **手机扫码登录**（macOS、Windows、Android 均支持）：在客户端登录页生成一次性登录二维码，用已经存有该账号 Passkey 的手机扫描二维码并打开 `/device` 页面确认即可，非常适合桌面端没有同步 Passkey 的情况。每个扫码请求有效期为 **3 分钟**且仅限使用一次。
3. **等待管理员批准或恢复身份**：尚未获批的成员需要先在浏览器完成登记并等待审批；已获批的成员则继续完成加密身份初始化或设备授权。[第一次和朋友通话](/guide/first-call)

## 常见安装与登录问题

- **Windows 安装程序无法运行或报错**
  请先用 `winver` 核对系统是否为 Windows 11 24H2（内部版本 `26100`）及以上且为 `x64` 架构。
  > [!WARNING] 卸载 Windows 版会清除本地设备身份
  > `Setup.exe` 的卸载程序会清理应用数据目录（包含本机设备私钥与设置）。升级或重装前，请务必确认手头仍有可用的 `.chirpkey` 恢复文件与密码，或留有另一台仍处于授权状态的旧设备！
- **客户端提示「版本过旧，需要更新」**
  管理员已在管理台提高了该平台的最低版本要求（`minimum_version` / `minimum_build`）。请联系管理员获取新版安装包。正在进行中的旧会话通常不受影响，但下次重新登录时必须升级。
- **提示「服务器配置无效」或「时间校验失败」**
  - 检查输入的 URL 是否准确，以及设备当前网络能否访问该域名。
  - 若客户端提示 `NETWORK_TIME_REQUIRED`，说明设备本地系统时间与网络标准时间偏差过大，或 UDP 123（[NTP](https://datatracker.ietf.org/doc/html/rfc5905)）校时受阻，请开启系统自动对时后重试。
  - 若连接正常但提示授权签名无法验证，请向管理员确认客户端公钥是否与服务端签发种子匹配。[故障排查](/hosting/troubleshooting)
