# 管理台与管理员指南

Chirp 内置了一个独立的 Web 管理台，访问地址为你的服务器公开域名下的 `/admin/`（例如 `https://voice.example.com/admin/`）。所有管理台操作都需要有效的管理员浏览器会话（有效期 8 小时，写入操作额外校验请求 Origin），而**授予或撤销管理员角色本身只能通过服务器本机 CLI 执行**，网页端无法自助提权。

## 登录与权限边界

1. 在浏览器打开 `/` 完成 Passkey 登录，如果当前账号拥有管理员角色，登录页会显示「**进入管理台**」入口（或直接访问 `/admin/`）。
2. 当管理员账号被停用、删除或被 CLI 降级为普通成员时，其现有浏览器管理会话会立即失效。
3. 管理台内置中英文切换与浅深色自适应，所有敏感操作（如删房、撤设备、封禁）均带有二次确认弹窗并写入服务端审计日志。

## 五大管理视图详解

### 1. 成员（Members）

查看空间内所有已批准成员的账号状态（正常 / 已封禁）、所在房间、加入时间以及最近一次客户端会话，并支持按昵称或成员 ID 实时搜索与筛选（全部 / 正常 / 已封禁）。

- **修改成员昵称**：通过「编辑」打开「修改成员昵称」弹窗更新成员昵称（1–80 个字符，下次入组时同步）。
- **永久封禁**：成员操作栏提供独立的「**永久封禁**」操作，确认后立即终止其活跃会话并移出所有媒体连接，同时将账号与全部关联设备加入不可解除的永久黑名单（原用户名不释放）。
- **强制下线**：仅结束成员当前的原生客户端会话并断开语音连接，不封禁账号，成员随后可重新使用 Passkey 登录。
- **设备管理与永久黑名单**：点击「设备管理」可查看该账号已登记的设备列表（名称、平台、设备指纹、首次登记与最近登录时间），也可以在顶部打开全站的「永久黑名单」。
  > [!CAUTION] 管理员撤销最后一台有效设备会永久封禁账号
  > 成员在客户端自助操作时，系统会阻止撤销最后一台设备。但管理员在管理台可以强行撤销成员的设备；一旦撤销了某个账号的**最后一台有效设备**（哪怕是管理员自己的账号），该账号与关联设备会被立即写入不可移除的黑名单并永久封禁，且原用户名不会释放，原有的 Passkey 或 `.chirpkey` 均无法解封。
- **删除成员**：彻底删除账号记录并清理其当前媒体连接。系统内置「**最后一位管理员保护**」——若空间内只剩一位有效管理员，无法通过网页删除或停用该账号。

### 2. 申请（Requests / 加入申请）

处理新成员在 `/register` 提交的加入申请（系统最多保留 **100 条**待审核记录，建议定期清理过期或遗失编号的申请）：

- **开放新成员申请开关**：一键切换是否开放新成员注册（旁边配有「开放中 / 已暂停」状态标签）。关闭该开关暂停新申请期间，网页端无法提交新申请（包括已打开但尚未提交的登记流程），但**管理员仍可继续审核或删除之前已提交的待审核记录**，已批准的老成员登录也不受影响。若不慎锁定了全部管理员并关闭了注册，可在服务器 CLI 运行 `chirp admin reopen-registration` 恢复开放。
- **核对并批准 / 删除**：支持按「待审核 / 已通过 / 全部」筛选与搜索，每条申请编号旁均配有「**复制**」按钮。让新朋友把注册回执中的完整申请编号发给你，核对昵称与编号一致后再点击「批准加入」。若朋友忘记复制编号，直接删除该条待审核记录让他重新登记即可。

### 3. 房间（Rooms / 语音房间）

采用「左侧房间列表 + 右侧房间详情」的双栏工作区布局。新服务器默认自带一个名为「公开大厅」（内部 ID 为 `friends`，带有「默认大厅」徽章）的默认房间，你可以为它重命名、修改简介或设置密码，但默认大厅**不可删除**（危险操作区会自动隐藏删除按钮）。

- **新增与删除房间**：点击右上角「**新增房间**」弹窗创建额外语音频道；在非默认房间的「危险操作」区删除正在通话中的房间时，服务端会立即撤销该房间的全部入房授权并清理媒体连接，但成员仍保持在线登录状态，可进入其他房间。
- **房间名称与简介**：名称支持 1–80 个字符；房间简介支持 1–280 个字符（带实时 `0 / 280` 字数统计）并允许换行，清空保存则恢复默认说明。两者修改后均实时同步到客户端列表，且**不会**中断房间内正在进行的通话。
- **入房密码**：支持设置 **8–128 个字符**（UTF-8 最长 512 字节，首尾空格参与精确匹配，输入框支持切换显示/隐藏明文）的房间密码，服务端使用随机盐 + [Argon2id](https://datatracker.ietf.org/doc/html/rfc9106) 哈希验证。为防止在线暴力猜解，服务端在每位成员、每个房间维度强制执行 **30 秒内最多 5 次失败尝试** 的限流（触发后返回 `429 ROOM_PASSWORD_RATE_LIMITED`，跟踪窗口上限 256 条）。
  ::: info 密码变更只约束新入房
  修改或取消房间密码**只影响后续尝试加入的新成员**，不会踢出已经在房内通话的成员，密码本身也不参与语音加密。若需立即清场，请使用「结束当前通话」或逐个移出成员。
  :::
- **当前媒体连接与控场**：实时查看当前房间的 LiveKit 媒体参与者列表，支持单独**移出房间**（仅撤销该次入房资格，账号仍保持登录）或一键**结束当前通话**（断开该房间全部安全群组与媒体连接）。

### 4. 版本（Versions / 客户端版本）

顶部以四张平台交互卡片分别展示 `iOS`、`macOS`、`Windows` 和 `Android` 的当前策略概览（编辑尚未保存时会显示「未保存」徽章），点击卡片即可在下方双列配对表单中修改，保存后立即对所有新发起的发现请求与登录生效（已在线的老通话不受影响）。

| 字段 | 格式与规则 | 作用 |
| --- | --- | --- |
| **最新版本号 / 最新构建号** | 三段数字（如 `2026.11.24`）+ 正整数构建号 | 用于客户端提示“有新版本可用”。 |
| **最低支持版本号 / 最低构建号** | 须不高于对应的最新版本与构建号 | 先比较三段数字大小，版本相同时再比较构建号；低于最低要求的客户端在发现、兑换或扫码领取环节将被拒绝，并收到 `CLIENT_UPDATE_REQUIRED` 提示。 |

### 5. 状态（System / 服务状态）

顶部四格概况卡片实时展示「有效成员 / 当前通话人数 / 待审核申请 / 语音服务」状态（点击卡片可直接跳转对应视图），页面下方展示 LiveKit 管理接口连通状态、SQLite 引擎版本、传输协议（`UDP · 端到端加密`）、单设备在线策略以及快速「健康检查接口」入口（`/healthz`）。

## 管理员 CLI 命令速查

涉及角色授予、降权、初始引导及应急维护的操作必须在部署主机上执行。进入 `~/chirp` 目录，使用 `sudo docker compose exec app /usr/local/bin/chirp` 调用以下子命令：[CLI 源码](https://github.com/YouZiFeiLe/Chirp/blob/main/cmd/chirp/main.go)

| CLI 命令 | 适用场景与说明 |
| --- | --- |
| `admin bootstrap --request-id <完整编号>` | 批准指定待审批申请并创建全库**首位**管理员（每个数据库仅限成功一次）。 |
| `member list` | 以 JSON 格式列出全部成员及其 `id`、昵称、启用状态与管理员标记。 |
| `admin grant --id <成员ID>` | 将已有成员设为管理员。 |
| `admin grant --request-id <完整编号>` | 直接将一条待审批申请批准为管理员。当原有管理员全部丢失 Passkey 时，可借此重新注册并恢复管理权限。 |
| `admin revoke --id <成员ID>` | 撤销指定成员的管理员角色（同样受「最后一位管理员保护」约束）。 |
| `admin reopen-registration` | 恢复开放新成员网页注册。 |
| `member disable --id <成员ID>` | 永久停用指定成员账号（同样保护最后一位管理员）。 |
| `version` | 输出应用版本号、SQLite 目标版本与数据库 schema 版本号。 |
